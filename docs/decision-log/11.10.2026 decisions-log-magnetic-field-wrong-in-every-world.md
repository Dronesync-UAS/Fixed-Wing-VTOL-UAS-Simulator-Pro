Magnetic field was sdformat's placeholder in every world (11 October 2026)

**Symptom:** repeating `WARN [health_and_arming_checks] Preflight Fail: Yaw estimate error`,
blocking arming, after the Magnetometer system was added earlier the same day.

**Cause.** All five worlds carried `<magnetic_field>6e-06 2.3e-05 -4.2e-05</magnetic_field>`. That
is **sdformat's own default value** (spec default `5.5645e-6 22.8758e-6 -42.3884e-6`) rounded off -
not a value for anywhere these worlds are placed. The 22 August entry records adding this element
to fix a yaw error, which is worth correcting: adding a placeholder is not the same as adding the
right value, and until today nothing read it.

**Why it surfaced only now.** Until the Magnetometer system was added, nothing simulated a
magnetometer, so the world's magnetic field had no consumer at all. With the system present PX4
receives a simulated field and compares it against what its own world-magnetic model expects at the
GPS position. With a placeholder field the two disagree and the EKF will not converge on heading.
This also means the 22 August "fix" cannot have worked through the mechanism assumed at the time.

**How wrong it was.** Computed from IGRF via the `ppigrf` package for each world's own declared
latitude, longitude and elevation, at 2026-10-11. The placeholder is 48,260 nT, declination
14.62°, inclination 60.49°:

| World | Place | Real field | Declination | Inclination | Error vs placeholder |
|---|---|---|---|---|---|
| `training_area.sdf`, `flat_test.sdf` | Hoggar, Algeria | 38,264 nT | 1.53° | 28.08° | **32° inclination, 10 µT** |
| `training_area_blackrock.sdf` | Black Rock, USA | 49,607 nT | 12.82° | 64.24° | 4° inclination |
| `training_area_nullarbor.sdf` | Nullarbor, Australia | 58,088 nT | 3.68° | **−64.31°** | **125°, sign inverted** |
| `training_area_uyuni.sdf` | Uyuni, Bolivia | 22,410 nT | −9.33° | **−19.27°** | **80°, sign inverted** |

The two southern-hemisphere worlds are the worst: the real field there points *up* out of the
ground, and the placeholder points *down* into it. A single value cannot be right for four
locations spanning both hemispheres.

**Units and frame**, from the SDF spec rather than assumed: tesla, in the frame set by
`<spherical_coordinates>` — ENU in these worlds, so the vector is (East, North, Up). A negative Up
component means the field points into the ground, as in the northern hemisphere.

**Fixed by `tools/fix_magnetic_field.py`.** Per-world values embedded with their provenance, each
checked against the coordinates it was computed for and skipped with a clear message if a world has
since moved — so a relocated world cannot silently get the wrong field. Backups to `.sdf.premag`,
XML validated, auto-restored on failure, `--revert` and `--dry-run`.

The field drifts by tens of nT a year, so these values stay good for years. Recompute if a world's
coordinates change.

**Not yet confirmed as the cure for the yaw error** — the mechanism fits and the numbers are
indefensible either way, so the change is right on its own terms, but it needs a restart and a look
at whether the warning stops. If it continues, the next suspect is PX4's own EKF magnetometer
settings rather than the world.

**Separate, still open: no aircraft visible in Gazebo and an empty entity tree**, while the PX4 log
shows the model spawning cleanly (`gz_bridge: world: flat_test, model name: standard_vtol_0`, no
error). That points at the GUI rather than the spawn — most likely a leftover Gazebo server with
the GUI attached to the wrong one. Needs `pgrep -af 'gz sim'` and `gz model --list` to confirm.

**Also noted in the same log, and the strongest evidence yet for the systems experiment:**

    INFO [airspeed_selector] No airspeed sensor detected. Switch to non-airspeed mode.
    INFO [airspeed_selector] Airspeed sensor healthy, start using again (-1, 1)

PX4 found an airspeed sensor where it previously had none. That is the AirSpeed system added today
doing exactly what was hoped, and it makes the missing-systems hypothesis materially stronger than
"the spiral did not happen once".

# 14 Oct 2026 - A console shaped like QGroundControl, fed by its map

Worked overnight, on instruction, with the brief: pair this station with
real QGroundControl, replicate QGC's design "in all details including
sizes", keep all forty-two instructor controls, and verify rather than
assume.

## The decision behind it

Running QGC beside this station for an afternoon settled a question that
had been open:

* **QGC is the better ground station.** Years of work, used operationally,
  and it is the interface a student will meet in the real world. Students
  fly on standard QGC.
* **This is the better training device.** Failure injection, scenario
  control, weather, the checklist, the records. QGC cannot do any of it
  and nothing off the shelf replaces it.

So they are not competitors. The instructor's console keeps its forty-two
controls and takes QGC's LAYOUT, so that an instructor glancing between
the student's screen and their own is reading the same shapes in the same
places rather than translating between two designs.

Served at `/pro`. `/` and `/classic` are untouched, which is what was done
for the panel grid when the current console was new.

## Nothing here was estimated from a screenshot

QGC is open source, so the numbers came from its source at the exact
version installed (v5.1.5, commit 3a67d31) and from measuring the running
application maximised at 1854x1011.

| what | value | where it came from |
| ---- | ----- | ------------------ |
| toolbar height | 66 px | measured: rows 0-65 are flat window colour, variance 11; the map below jumps to 29. `ScreenTools.qml`: `toolbarHeight = defaultFontPixelHeight * 3` |
| tool strip width | 56 px | measured x=6..61. `ToolStrip.qml`: `width = defaultFontPixelWidth * 7` |
| margin | 6 px | measured left edge. `FlyViewWidgetLayer.qml`: `_toolsMargin = defaultFontPixelWidth * 0.75` |

Those give **defaultFontPixelHeight = 22** and **defaultFontPixelWidth =
8**, and they cross-check: 8 x 0.75 is the 6 px that was measured
independently. Everything in the stylesheet is expressed in that pair, as
QGC expresses everything in its own, so changing them rescales the console
the way changing QGC's font scale rescales QGC.

The palette is `QGCPalette.cc`. Its macro is `DECLARE_QGC_COLOR(name,
lightDisabled, lightEnabled, darkDisabled, darkEnabled)`, so the FOURTH
value is the one a dark-themed QGC uses - `#222222` window, `#00e04b`
green, `#f32836` red, `#de8500` orange.

**One layout error was found by reading the source rather than the
picture.** `FlyViewBottomRightRowLayout.qml` puts the telemetry bar and
the instrument panel in ONE row anchored bottom-right. The first build had
telemetry centred along the bottom with the compass off on its own, which
is what it looks like at a glance and is not what it is.

## The map is QGC's own imagery, not an imitation

The plan view was one satellite image, fetched once: 1964 px across 4 km,
2.04 metres per pixel, and zooming in only enlarged those pixels. QGC
looks sharper because it draws a tile pyramid per zoom level.

Rather than build a second fetcher, the station now reads the tiles QGC
has already downloaded, from
`~/.cache/QGroundControl/QGroundControl/QGCMapCache/qgcMapCache.db`,
**read-only** so a bug here can never damage an instructor's cache.

The hash format came from `QGCMapUrlEngine.cpp`:

    QString::asprintf("%010d%08d%08d%03d", hash, x, y, z)

provider, x, y, zoom. Checked against the cache before any code was
written: the first row decodes to 37.4138 N, 122.0004 W - Mountain View,
QGC's default map position, exactly where a first run caches tiles.
Google Hybrid is provider 4 because `UrlFactory::_providers` lists Street,
Satellite, Terrain, Hybrid from 1, and 4 is both what this machine's QGC
is set to (`mapProvider=Google, mapType=Hybrid`) and where most of its
cached tiles are.

**Tiles fall back to a parent when the exact zoom is not cached.** QGC
caches whatever zoom it was looking at; the zoom that best fits our canvas
usually misses. Measured: the Nullarbor had full coverage at zoom 17 and
none at the zoom 20 the canvas wanted. Drawing the right quarter of an
ancestor is what every slippy map does, and it is the difference between a
picture and an empty grid.

### What this does not do

Download. A training area QGC has never looked at has no tiles, and the
answer is QGC's own **Offline Maps** download, not a second fetcher here -
partly to avoid doubling the traffic, and mostly because whose terms the
imagery sits under is not a decision for this project to take quietly.

## What was found by testing rather than reading

**The GPS failure control was reporting an injection it never made.** It
started a proxy that rewrites GPS only in the stream to QGC, needs port
plumbing the launcher does not do, and takes its commands by typing - so
started as a background script its command thread died at once with
`EOFError`. Pressing the button said "GPS failure injected." and the
satellite count stayed at 10.

It now sets PX4's own `SIM_GPS_USED` to 0. `SensorGpsSim.cpp` gives a 3D
fix at 4 satellites or more and no fix below, so 0 is a real loss inside
PX4's sensor pipeline. Measured end to end:

    SIM_GPS_USED 10 -> satellites 10, fix 3, tail light (0.05, 0.9, 0.15)
    SIM_GPS_USED  0 -> satellites  0, fix 0, tail light (0.95, 0.06, 0.06)
    cleared         -> satellites 10, fix 3, green again

`MAV_CMD_INJECT_FAILURE` was the obvious answer and was tried first. It is
handled by `simulator_mavlink`, the old jMAVSim and Gazebo-classic back
end; these worlds run Gazebo Harmonic through `gz_bridge`, which does not
handle it. PX4 never acknowledged it and nothing moved.

**The console's own description of the lights was out of date** - still
"red to port, green to starboard, white at the tail", a set the aircraft
no longer carries. A student reads that and believes it.

## What is checked

`tools/test_pro_console.py`: all forty-two controls reachable, no element
id appearing twice, the layout constants still QGC's, the tile hash and
the Mercator arithmetic both ways, and the whole console driven in a
browser at QGC's own window size - checklist, flight log, the exit
question, and tiles actually drawn.

`tools/test_night_ops.py` section 4b covers the GPS failure control,
including that an injection the aircraft does not confirm is NOT claimed.

## Still open

* **Mission planning** is reachable only through Settings. QGC has a Plan
  view; this does not.
* **`/pro` is not the default.** `/` has a Pro button; the swap is a
  decision for whoever teaches on it.
* **Imagery coverage** is whatever QGC happens to have cached. Full
  coverage needs one Offline Maps download per training area.
* The dark ground in the seven plane worlds, unchanged from 13 Oct - see
  that day's entry for which two candidates are left.

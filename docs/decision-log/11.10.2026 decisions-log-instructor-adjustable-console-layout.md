Instructor-adjustable console layout + layout lock (11 October 2026)

**Problem raised:** the instructor has to scroll up and down to see all the console panels, when
everything should be visible at once on the station screen. Follow-on request: let the instructor
move and resize panels to suit themselves, then lock the arrangement so it can't be nudged by
accident mid-session.

**Root cause of the scrolling, found before building anything:** `.grid` carried
`max-width: 900px`, and the camera and plan-view panels each carried the same cap inline. On a
wide station screen the panels were therefore squeezed into a ~900px column and stacked
vertically, with most of the screen width unused. Not a shortage of space - a cap.

**What changed:**
- The grid is now 12 columns at full width, and every panel lives in it - the button panels, the
  FPV camera panel and the flight-path plan view, which were previously siblings outside the
  grid. Panels declare how many of the 12 columns they span rather than a pixel width, so a saved
  layout still tiles sensibly if the station ever runs on a different screen.
- Defaults aim at one screenful: the two picture panels take half the width each (one row), the
  seven button panels a quarter each (two rows). Whether that lands exactly depends on the
  screen, which is why it's adjustable rather than fixed.
- Each panel has a stable id (`panel-flight-ops`, `panel-fpv`, `panel-flightpath`, ...) derived
  from its category, so a saved layout keeps pointing at the same panel across restarts and as
  plugins are added or removed.
- Drag a panel by its heading to move it; drag the corner grip to resize. Spans clamp to 2-12
  columns, heights to 120-2000 px, so no panel can be shrunk out of reach or made to push the
  rest off screen.
- The plan view's canvas was a fixed 420 px tall, so resizing its panel did nothing visible. It
  now fills its panel, and the existing `fit()` timer redraws it at the new size each second.

**The lock.** A button in the top bar, **locked on every page load**, deliberately: the
instructor opts in to editing, so a stray drag during a session can't rearrange the console.
Unlocking shows the drag handles, the resize grips and a Reset button.

**The lock is an accident guard, not access control.** Anyone at the keyboard can unlock it. A
PIN was considered and rejected: with no user accounts on a local app, the PIN would live in a
file on the same machine, making it a thing to lose rather than real security. If genuine
student/instructor separation is ever needed, it belongs at the application level, not on this
button.

**Where the layout lives:** `~/uas_sim_logs/gcs_layout.json`, next to the event log - so it
survives a browser reset or reinstall, is the same for whoever opens the station, and is picked
up by the same 20:30 cron backup as the event log. Per-browser `localStorage` was the easier
option and was rejected for those reasons. A corrupt or unreadable layout file falls back to the
default arrangement rather than stopping the station.

**Validation is server-side**, not just in the browser: panel ids must match
`[A-Za-z0-9_-]{1,60}`, spans and heights are clamped, and anything else is rejected with a 400
rather than written to disk.

**CAP722B consideration.** The limit banner and the feeds/health readouts sit in the top bar,
outside the grid, so they cannot be dragged away, resized or hidden by a personalised layout.
That was a deliberate check, not luck - a layout an instructor can freely rearrange must not be
able to hide the compliance-critical readouts. Recorded in the code as `PINNED_OUTSIDE_GRID`.

**Tested** via `tools/offline_render_check.py` plus a live server run: page serves with all nine
panels in the single grid, layout saves, reads back, resets, and rejects malformed input.
Not yet used in a real session on the station screen - the default arrangement should be checked
against the actual Getac X600 display and adjusted from there.

## Same day, follow-up after first look on the station

Two faults found when the instructor actually opened it, both in the above:

**The lock button was invisible.** It had been appended to the top bar, which already carries the
brand and nine readouts. With no wrapping and the body set to `overflow: hidden`, the controls
were pushed straight off the right-hand edge - so the layout could not be unlocked, and the
drag/resize handles (which only appear when unlocked) were unreachable. Moved to a small toolbar
at the top of the main area, which cannot overflow. Lesson: don't append to a bar that is already
full.

**The default panel sizes still didn't fit.** The 900px cap was the cause of the original
scrolling, but removing it was not enough - the chosen default spans were a guess at the station's
screen, and guessed wrong. Replaced with a **Fit to screen** button that measures the actual
viewport and shrinks panels until the console fits, and which also runs automatically on first
load when no layout has been saved yet. So the default is now "fits this screen", not "fits the
screen I assumed".

It shrinks column spans rather than forcing panel heights, deliberately: the camera panel is a
16:9 stream, so halving its width halves its height, whereas capping its height would crop the
picture. Tallest panel gives way first, so the two picture panels shrink before the button panels
get squeezed into unusably narrow columns. If it still cannot fit, it says so rather than
pretending it worked.

## Auto-refit on window resize

Tiling the station beside the Gazebo window makes it narrower, and a layout
fitted to the old width then scrolls again - meaning Fit to screen had to be
clicked by hand after every resize. The station now re-fits itself on resize,
debounced, and **only when the content actually overflows**. A hand-arranged
layout that still fits is never rearranged underneath the instructor, which was
the point of the lock.

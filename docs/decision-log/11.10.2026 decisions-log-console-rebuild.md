# The console rebuilt around the picture — 11 October 2026

## What was wrong with the grid

The old page was fifteen panels of equal weight. The thing an instructor
actually watches — the aircraft — was one tile among them, which is why
every session also had the Gazebo window open, and why half a tiled screen
went on a window whose only job was one picture.

## What replaced it

One view fills the screen; everything else arranges around it.

- **hero** — chase camera, nose camera or map, swapped by clicking a corner
  tile or by the tabs
- **left rail** — flight ops, then an Emergency section
- **right rail** — the instructor-only controls
- **bottom band** — the flight parameters, with the attitude gyro set across
  its top edge, and the CAP722B strip beneath

Two layouts, because the right answer depends on the room:
**Pilot** runs the picture edge to edge with the rails floating over it;
**Station** insets the picture behind solid rails so nothing ever covers it.
These are the two designs that were drawn as separate options — they are one
console with a switch, and the switch is saved.

## Decisions worth keeping

**One element per view.** The three views are built once and *moved* between
the hero and the tiles with `appendChild`. There is deliberately no second
`<img>` pointed at a feed: each MJPEG stream is an HTTP connection the
station encodes frames for, so a duplicated tag would double the camera work
for a picture nobody is looking at. `tools/offline_render_check.py` asserts
each feed appears exactly once, because the obvious way to write this page
is the wrong one.

**No canvas code was rewritten.** The nose camera's attitude overlay and the
map's terrain, rings and track are the existing, proven drawing code in
`EXTRA_SCRIPT`, reached through the same element ids it has always used.
The new page provides those ids and nothing more.

**The classic page stays at `/classic`.** It costs one route and removes the
risk of discovering a gap mid-lesson.

**Rails are ordered by what a pilot reaches for.** Plugins load in filename
order, which had put TERMINATE FLIGHT third in the left rail — between
DISARM and HOLD, the worst place on a console for a control with no undo.
`RAIL_ORDER` fixes the sequence and termination moved to its own Emergency
section at the foot of the rail.

**The attitude overlay is hidden in a tile.** It is drawn for a full-size
view; at 212 px its pitch ladder and readout boxes are unreadable and spill
across the picture. The first browser screenshot showed exactly that.

**Saved state is clamped, not trusted.** Hero, layout and the two tile
frames live under a `console` key in the existing layout file, so a saved
panel arrangement from the classic page is untouched. A tile saved at a
negative size or off-screen would be unreachable on the next load with no
way back but deleting the file, so sizes are clamped server-side.

## Testing, and what the browser test caught

`tools/test_console_browser.py` serves the real page with stubbed JSON and
drives it in Chromium: no JavaScript errors, no failed requests, the hero
laid out with real size, each view present exactly once, tabs and tile
clicks swapping the main screen, the layout switch actually insetting the
picture, a tile that drags, and telemetry reaching the readouts.

This was worth building rather than trusting the HTML. The console is mostly
JavaScript now, and a single syntax error in it shows as a black screen with
every control gone — the one failure the offline check cannot see.

Its first run failed three checks, and all three were real:

1. A 404 on every load (`/favicon.ico`) that nothing else would have
   reported.
2. The hero holding the wrong view, and the layout switch appearing to do
   nothing — both because the test was reading, and writing, the real
   `~/uas_sim_logs/gcs_layout.json`. It had already overwritten the saved
   console state with a clamped test value. Now it renders against a
   throwaway file, the same isolation the event-log stub exists for.

`tools/offline_render_check.py` gained a console section covering the page's
assembly, the rail split, every plugin being reachable from one rail or the
other, and the saved-layout clamping.

## First run on the machine, and the five faults it found

All five were real, and four of them were invisible to every check that
existed.

**The map drew a quarter of the screen.** The classic page's stylesheet is
still loaded for its canvas code, and it pins `#flightpath` to a fixed
`height: 420px`. An id selector outranks the new class rule, so the map drew
420 px tall inside a 900 px hero and the rest went black. Overridden by
`.view canvas#flightpath` — ancestor plus id, which outranks it without
`!important`. The browser test now asserts the canvas is as tall as the hero,
because this is the kind of fault that comes back the next time a stylesheet
is added.

**The chase camera looked poor** because 640×360 was being stretched across a
1400 px hero. Raised to 1280×720. The headroom this relies on is measured,
not assumed: the station reported 30 fps with the camera already running at
the smaller size. The `<image>` block is documented as the first thing to
turn down if the simulator slows.

**Button labels were written for a wide panel.** "RETURN TO LAUNCH" and
"HOVER FLIGHT (MC)" in a 120 px rail wrapped and sat left-aligned. The rail
now has its own shorter names (`RAIL_LABELS`), text is centred, and the
status dot is positioned absolutely so a lit control is not off-axis from an
unlit one. The test asserts no button's text is wider than its rail.

**The right rail held more than fits.** Every section is now collapsible, and
Function Test and Experimental start collapsed on a console that has never
been arranged — so Freeze is on screen without scrolling. Which sections are
shut is saved with the rest of the console state.

## Making the three views sharp

"the quality and resolution of the viewable screens is poor (chase, nose,
map)". Three separate causes, one per view.

**The canvases were drawn at one device pixel per CSS pixel.** `fit()` set
`canvas.width = clientWidth`, so on any display with a pixel ratio above 1
the map and the attitude overlay were drawn small and scaled up by the
screen. It now sizes the backing store by `devicePixelRatio` and scales the
context, keeping `cssW`/`cssH` so the drawing code carries on working in CSS
pixels. Capped at 2 — past that the cost grows faster than anyone can see.

**A canvas kept the size it was last fitted to.** The map is refitted once a
second, so moving it from a 208 px tile into the hero left a tile-sized map
stretched across the screen for up to a second. `EXTRA_SCRIPT` now exposes
`window.gcsRedraw`, and the console calls it the moment a view swaps, the
layout changes, or a tile is resized. The browser test caught this one by
accident, and it now checks for it on purpose.

**The JPEG settings were a radio link's, not a loopback's.** Quality 70 left
visible artefacts on the horizon, and serving 10 frames a second from a
camera publishing 30 threw two of every three away for a saving nobody
needed. Both feeds are now quality 88 at 25 frames a second.

The chase camera itself went to 1600×900, which matches the hero on this
screen. The budget is held by cost rather than pixels, and the test asserts
it: 21.6 megapixels a second against the nose camera's 36.9, so it remains
the cheaper of the two cameras this machine already runs.

**Not yet flown.** Nobody has taken off with it. The browser test proves it
works; only a lesson proves it is better than the grid, and `/classic` is
there until then.

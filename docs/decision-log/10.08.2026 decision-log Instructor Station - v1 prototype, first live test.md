Instructor Station — v1 prototype, first live test (10 August 2026)

Built and tested a first working version of the CAP722B-required instructor controls (freeze, reposition, malfunction injection), against the live PX4 v1.15.4 + Gazebo Harmonic + Baylands setup on the X600.

Confirmed working, end-to-end:

Freeze/resume simulation — via Gazebo Harmonic's built-in /world/<world>/control service. Confirmed: pauses/resumes the simulation clock and physics on command. Note: while frozen, QGroundControl shows "Comms Lost" — expected behaviour due to PX4's lockstep timing with Gazebo, not a fault.
Reposition aircraft — via Gazebo Harmonic's built-in /world/<world>/set_pose service. Confirmed: aircraft moves to commanded position; QGroundControl reflects the new position correctly.
Malfunction injection (mechanism) — via PX4's built-in MAV_CMD_INJECT_FAILURE system, connected using pymavlink over UDP port 14540. Confirmed: commands reach PX4 successfully and are acknowledged, for both gps off and motor off.

Known limitation identified:

GPS failure injection has no visible effect in QGroundControl — command is sent and acknowledged by PX4, but GPS satellite count/status doesn't change. This matches a known, still-open PX4 bug report (GitHub issue #22296, opened Nov 2023) describing identical behaviour — not specific to our setup. Motor failure injection was also sent successfully but not yet visually confirmed (needs an in-flight test, since a stopped motor is easier to observe mid-flight than on the ground).
Implication for CAP722B 5.5(l) (GPS performance modelling, nominal/degraded): PX4's built-in failure system cannot currently be relied on for GPS degradation scenarios. A different approach (e.g. a custom Gazebo GPS noise/dropout plugin, rather than PX4's failure-injection path) will likely be needed here — flagged as a follow-up, not yet designed.

Confirmed world/model names for this setup: world = baylands, model = standard_vtol_0.

Two script bugs found and fixed during testing (both now corrected in the prototype code): (1) the PX4 connection direction was backwards — PX4 expects the offboard program to listen on port 14540, not connect out to it; (2) the installed pymavlink version didn't recognise the failure-injection command by name, fixed by using its fixed numeric ID (420) instead.

Not yet tested: motor failure with the aircraft actually in flight; environment control (wind/turbulence); scenario loading; limit-exceedance warnings.
